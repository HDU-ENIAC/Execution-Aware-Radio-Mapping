# Dataset Format

The source data consist of local 3D received-power volumes from per-transmitter
WinProp simulations. Data files are not included in this repository.

## HDF5 Structure

Let N be the number of target volumes and K the number of stored sparse inputs.

| Key | Shape | Meaning |
| --- | --- | --- |
| `target` | `(N, 32, 512, 512)` | Complete normalized power, float32 |
| `building_mask` | `(N, 32, 512, 512)` | Boolean occupancy; True means building |
| `input` | `(K, 32, 512, 512)` | Stored sparse power, float32 |
| `target_index` | `(K,)` | Target associated with each sparse input |
| `target_positions` | `(N, 2)` | Crop origin `(x, y)` in the full-map array |

Spatial axes are `(z, y, x)`, with 1 m grid spacing. Free-space power is
normalized to `[0, 1]`, not dBm; building entries are `-1`. Use the explicit
building mask to identify occupied voxels. The recorded height range does not
necessarily include every building's roof. Crop origins are not transmitter
coordinates.

Stored sparse inputs are separate from the measurements generated by the path
planner. A zero value alone does not identify an unobserved voxel; route-based
observations use explicit coordinates and readings.

## Reading Example

```sh
python examples/read_dataset.py --help
```

The example reads one volume at a time rather than loading an entire HDF5 file
into memory. City geometry, simulator projects and third-party datasets are
not distributed here; any future data release requires separate authorization.
